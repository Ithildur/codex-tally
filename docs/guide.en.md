## Configuration

Flags `--host` and `--port` override their environment variables. The default listener is `127.0.0.1:4318`. Ports must be between 1 and 65535. A specific listen IP must belong to the machine. Use its actual IP and port when connecting; listening on all interfaces does not allow arbitrary hostnames.

| Variable | Default or purpose |
| --- | --- |
| `HOST` | `127.0.0.1`; IPv4, IPv6, or localhost |
| `PORT` | `4318` |
| `PUBLIC_ORIGIN` | HTTPS origin for a reverse proxy, such as `https://usage.example.com` |
| `PUBLIC_SHARE` | Set to `1` to enable anonymous sharing |
| `CODEX_TALLY_PASSWORD` | Fixed password, at least 8 Unicode characters; otherwise a random 12-character password per start |
| `DASHBOARD_STATE_DIR` | `.state-codex-tally` next to the executable |
| `CODEX_HOME` | Current user's `.codex` directory |
| `TZ` | System timezone; accepts IANA names such as `Asia/Hong_Kong` |
| `PRICING_FILE` | Custom price JSON; see [costs](#costs) |
| `CODEBURN_CFG` | `~/.config/codeburn/config.json` |
| `FX_CACHE` | `~/.cache/codeburn/exchange-rate.json` |
| `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` | Proxy settings for upstream HTTP requests |

```bash
CODEX_HOME=/path/to/.codex TZ=Asia/Hong_Kong ./codex-tally
```

```powershell
$env:CODEX_HOME = "$env:USERPROFILE\.codex"
$env:TZ = 'Asia/Hong_Kong'
.\codex-tally.exe
```

On native Windows the default data path is `%USERPROFILE%\.codex`; Linux, macOS, and WSL use `$HOME/.codex`. `export` and `sync` resolve `-codex-home`, then `CODEX_HOME`, then the user default. Spaces, Unicode, and a `~` prefix are supported. Relative paths use the working directory.

Windows and WSL homes are separate; they are not scanned or merged automatically. Run inside WSL for WSL sessions, or explicitly point to an accessible data directory.

The timezone database is embedded. CLI `-timezone` overrides `TZ`. If the server returns the native `Local` timezone, the browser formats dates in its own timezone; set `TZ` explicitly when accessing the dashboard from another timezone.

### Language

The dashboard and Pages hub default to the browser language. Chinese uses `zh-CN`; all other languages use English. A saved choice overrides browser detection, and an explicit URL `lang=en` or `lang=zh-CN` overrides both. **Auto** restores browser detection. Changing language reloads the page, preserving the tab, date range, calculator token inputs, prices, and selected model. If translations fail to load or take longer than five seconds, the interface temporarily falls back to Chinese without changing your language preference. Reload after recovery to use your chosen language again.

Shared links generated by the dashboard include the selected language. Existing online share URLs without `lang` remain Chinese. Pages builds contain both languages: `tokens/auto.html` is Chinese; `tokens/auto.en.html` is English. SVG variants use the same convention, such as `tokens/dark.en.svg`, and require no JavaScript to translate.

CLI flags and help are English. Startup messages and configuration errors follow `LC_ALL`, then `LC_MESSAGES`, then `LANG`: a Chinese locale uses Chinese, otherwise English. Underlying operating-system or upstream errors retain their original messages. The web language selector does not change terminal output.

### Authentication and state

The dashboard password is separate from Codex authentication. Generated passwords are printed once after a successful start; configured passwords are not logged. No password file is read or written. Sign-ins last 12 hours and are invalidated by a restart.

Use `CODEX_TALLY_PASSWORD`, not the old `DASHBOARD_PASSWORD`. Old `.state/password` files are unused. The default state directory changed from `.state` to `.state-codex-tally`; it is not automatically moved. You may move `sessions.json`, select the old directory with `DASHBOARD_STATE_DIR`, or let the app rescan. Do not migrate old password files. A parser-version change rebuilds incompatible caches automatically.

On Linux and macOS, state directories use mode `0700` and files `0600`. Windows uses inherited NTFS permissions; keep the executable and state under your user directory.

Account statistics read the access token and account ID from `CODEX_HOME/auth.json`. Run `codex login` as the same user when credentials expire. Codex Tally does not modify credentials or refresh tokens. Account queries do not currently support API-key credentials or OS keychains. Local statistics, export, and sync need no auth file.

## GitHub Pages and offline sync

Fork, clone, enable Actions, and select **GitHub Actions** as the Pages deployment source. Configure your Git identity and remote credentials, then run on the default branch:

```bash
./codex-tally sync
./codex-tally sync -components tokens,calls,cache,models
./codex-tally sync -components tokens
```

These are alternative publication choices. The default exposes tokens, calls, and cache rate; model details are opt-in. Keep your component selection consistent in scheduled jobs. Unchecking a field in the sharing hub only changes its display; it does not remove an exported field.

The workflow uses your default branch and the built-in Actions token, with no additional GitHub token or Codex secret. Without `site/usage.json`, deployment is skipped. Pull requests and other branches run checks only. The deployment URL is normally `https://<owner>.github.io/<repo>/`.

Only the current month is exported, according to the selected timezone. Unchanged values retain the previous collection timestamp and produce no new commit. Multiple computers writing the same snapshot overwrite each other; multi-device merging is not supported.

For fully offline export:

```bash
./codex-tally export -out site/usage.json
```

Copy that JSON to a connected machine's repository, then commit and push it:

```bash
git add site/usage.json
git commit --only -m "Update public usage" -- site/usage.json
git push
```

### Sync behavior

```bash
./codex-tally sync -repo /path/to/codex-tally -codex-home /path/to/.codex -log /path/to/codex-tally/.state-codex-tally/sync.log
```

`sync` owns only `site/usage.json`. It exports, validates, fetches, commits, and pushes using the current branch's upstream and existing Git authentication. Other staged and unstaged changes are preserved. It never force-pushes, merges, rebases, or pushes tags.

| Situation | Result |
| --- | --- |
| Values unchanged | No new commit |
| Fetch fails | Exported JSON retained for retry |
| Push fails | Local sync commit retained for retry |
| Remote is ahead or diverged | Update the branch and resolve conflicts manually |
| Unpublished non-sync commits | Review and push source changes first |
| Pending history includes fields no longer allowed | Clean up those commits before syncing |
| Fetch and push URLs differ | Configure one matching remote URL |
| Sync lock already exists | Confirm no sync is running before removing the reported lock directory |

Git hooks and signing still apply. Sync is limited to 10 minutes, and concurrent syncs in one repository are blocked. Scheduled jobs must authenticate and sign without interaction. Rotate long-running logs yourself. Raw remote errors are omitted to avoid exposing URL credentials; diagnose authentication with `git fetch` or `git push` under the same user.

### Preview and embed

```bash
./codex-tally build-pages -input site/usage.json -out _site
python3 -m http.server 8080 --directory _site
```

Open <http://localhost:8080/>. Build output must be empty; choose a fresh directory or remove the previous build. For a synthetic preview, use `internal/dashboard/testdata/public-usage.json` as input.

The Pages hub copies HTML, SVG, Markdown, or iframe output using the browser's current origin and repository path. Example English files:

```text
tokens/auto.en.html
tokens/dark.en.svg
hub/tokens-calls/light.en.html
hub/tokens-calls-cache/auto.en.svg
```

Themes are `auto`, `light`, and `dark`. Only permitted components and combinations are generated. A later successful deployment removes pages for excluded fields. Numeric components share a row and stack on narrow screens; model tables occupy a full row. Keep `embed.js` with iframe snippets so their height can follow the content.

Builds read only the public JSON and reject unknown fields, unsupported versions, and inputs over 1 MiB. Actions uploads only `_site`. Removing a published field does not erase old Git history.

## Scheduled sync

Complete one manual sync first. Run the job as the Codex user, replace the example paths, and ensure Git authentication is noninteractive. A computer that is off or offline cannot update Pages; the next scheduled run retries after it returns.

### Linux

Run `crontab -e` as your user, without sudo:

```cron
PATH=/usr/local/bin:/usr/bin:/bin
*/30 * * * * "/home/you/codex-tally/codex-tally" sync -repo "/home/you/codex-tally" -codex-home "/home/you/.codex" -log "/home/you/codex-tally/.state-codex-tally/sync.log"
```

Add other directories to `PATH` if Git or a credential helper needs them. Remove the cron entry to disable it; inspect `sync.log` for results.

### macOS

Create `~/Library/LaunchAgents/com.ithildur.codex-tally.sync.plist`. Replace every `/Users/you` with your actual home; plist paths must be absolute, without `~`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.ithildur.codex-tally.sync</string>
  <key>ProgramArguments</key><array>
    <string>/Users/you/codex-tally/codex-tally</string>
    <string>sync</string>
    <string>-repo</string><string>/Users/you/codex-tally</string>
    <string>-codex-home</string><string>/Users/you/.codex</string>
    <string>-log</string><string>/Users/you/codex-tally/.state-codex-tally/sync.log</string>
  </array>
  <key>EnvironmentVariables</key><dict>
    <key>PATH</key><string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
  </dict>
  <key>StartInterval</key><integer>1800</integer>
  <key>RunAtLoad</key><true/>
</dict></plist>
```

```bash
plutil -lint ~/Library/LaunchAgents/com.ithildur.codex-tally.sync.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ithildur.codex-tally.sync.plist
# Disable:
launchctl bootout gui/$(id -u)/com.ithildur.codex-tally.sync
```

This runs while the user is logged in; exact scheduling during sleep is not guaranteed.

### Windows

Run in your user's PowerShell. This task runs only while that user is signed in, reusing their Git Credential Manager or SSH agent without putting a password in the task.

```powershell
$repo = "$env:USERPROFILE\codex-tally"
$codexDataPath = "$env:USERPROFILE\.codex"
$arguments = 'sync -repo "{0}" -codex-home "{1}" -log "{0}\.state-codex-tally\sync.log"' -f $repo, $codexDataPath
$action = New-ScheduledTaskAction -Execute "$repo\codex-tally.exe" -Argument $arguments -WorkingDirectory $repo
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(1) -RepetitionInterval (New-TimeSpan -Minutes 30)
$principal = New-ScheduledTaskPrincipal -UserId ([System.Security.Principal.WindowsIdentity]::GetCurrent().Name) -LogonType Interactive -RunLevel Limited
$settings = New-ScheduledTaskSettingsSet -MultipleInstances IgnoreNew -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 12)
Register-ScheduledTask -TaskName 'Codex Tally Sync' -Action $action -Trigger $trigger -Principal $principal -Settings $settings

Get-ScheduledTaskInfo -TaskName 'Codex Tally Sync'
Get-Content "$repo\.state-codex-tally\sync.log" -Tail 30
# Disable:
Unregister-ScheduledTask -TaskName 'Codex Tally Sync' -Confirm:$false
```

Ensure `git.exe` is on the user's `PATH`. For WSL Codex, configure the Linux task inside WSL and keep the distribution running; do not substitute the Windows home directory.

## Remote access and online sharing

You can bind a LAN address with `--host`, or keep the default listener and use SSH forwarding:

```bash
ssh -L 4318:127.0.0.1:4318 user@server
```

Then open <http://localhost:4318>. A different local forwarding port is supported. For HTTPS reverse proxy access, configure `PUBLIC_ORIGIN` and a proxy such as Caddy:

```bash
PUBLIC_ORIGIN=https://usage.example.com ./codex-tally
```

```caddyfile
usage.example.com {
    reverse_proxy 127.0.0.1:4318
}
```

With `PUBLIC_ORIGIN`, login cookies require HTTPS. If the proxy runs elsewhere, configure a reachable `HOST` and restrict origin access to the proxy.

Enable anonymous sharing with `PUBLIC_SHARE=1`. Private dashboard routes still require a password. Online shares expose the cached month's local tokens, calls, cache rate, and models, excluding cost, quota, activity, and session details. Snapshots are regenerated after successful local cache updates. Visitors cannot trigger scans or widen the reporting range. The origin advertises a five-minute cache; embedding platforms may cache longer.

| Component | HTML | SVG |
| --- | --- | --- |
| Overview | `/share` or `/share/overview` | `/share/overview.svg` |
| Hub | `/share/hub?components=tokens,models` | `/share/hub.svg?components=tokens,models` |
| Tokens | `/share/tokens` | `/share/tokens.svg` |
| Calls | `/share/calls` | `/share/calls.svg` |
| Cache | `/share/cache` | `/share/cache.svg` |
| Models | `/share/models` | `/share/models.svg` |

Append `lang=en` for English, and `theme=auto`, `light`, or `dark`. Use `&` when a query already exists. Component order is fixed as `tokens,calls,cache,models`; missing selection means all four. Empty, duplicate, or unknown components return 400.

```html
<iframe data-codex-usage
        src="https://usage.example.com/share/tokens?theme=light&lang=en"
        title="Codex total tokens" width="480" height="240"
        sandbox="allow-scripts" loading="lazy"
        style="display:block;width:100%;max-width:480px;border:0"></iframe>
<script async src="https://usage.example.com/share/embed.js"></script>
```

```markdown
![Codex usage](https://usage.example.com/share/overview.svg?theme=dark&lang=en)
```

The sharing panel copies the browser's current protocol, host, and port. A localhost URL is only useful where that localhost service or forwarding exists. Individual numeric SVGs are 480 × 180; model and overview SVGs are 640 pixels wide with height based on rows. SVGs contain no scripts or external font/image dependencies.

To expose only shares, leave the dashboard on loopback without `PUBLIC_ORIGIN` and proxy only public paths:

```caddyfile
usage.example.com {
    @public path /share /share/*
    handle @public {
        reverse_proxy 127.0.0.1:4318 {
            header_up Host {upstream_hostport}
        }
    }
    handle {
        respond 404
    }
}
```

Keep management access local or through SSH. Only public routes should receive this Host rewrite. Remove `PUBLIC_SHARE=1` and restart to disable origin access; downloaded or cached copies cannot be recalled.

## Statistics and caches

Local usage reads `sessions` and `archived_sessions`. Final `token_usage_record` entries are deduplicated by response, including compaction. Legacy-only turns use `token_count`; the two record types are not added together. Reasoning output is already included in output tokens. Calls count usage records, not user interactions or HTTP requests. Activity reflects record timestamps, not continuous working time.

Account statistics use separate upstream daily data. Daily model share is each model/speed's usage value divided by the day's total usage values, rounded to three decimal places. It is not a token, cost, or quota percentage. Account responses lack model-specific token categories, so account costs are not estimated.

Time ranges are start-inclusive and end-exclusive. Last 7 days includes today and the preceding six calendar days. Weeks begin Monday. Quota windows use the upstream duration and reset time. Local statistics default to the 7-day quota window for Pro or the 5-hour quota window for Plus, preserving any range explicitly set in the URL. Pro does not expose a 5-hour filter. Missing quota windows are hidden; when quota data is unavailable, the default is Last 7 days. The account API's date timezone remains unverified.

The local tab offers **Live mode**, off by default. It refreshes local usage one second after each request completes, pauses when the page is hidden or another tab is selected, and retries failures after 30 seconds. Account usage and quota retain their normal caching policy. Large log files may take longer to parse; requests do not overlap. Unchanged files are reused without rewriting the disk cache or regenerating shares. A new month still updates the monthly snapshot.

| Data | Refresh behavior |
| --- | --- |
| Local sessions | Hourly scan; cached view followed by refresh; manual refresh available |
| Account statistics and quota | 30-minute success cache; retry after 30 seconds on failure; retain previous data |
| Quota windows | Expire when the window resets |
| Online shares | Publish after successful local cache updates |
| Pages | Update after successful deployment |

Local cache files are indexed by size and modification time and isolated by Codex directory. The cache contains usage events, not prompts or credentials. Incompatible parser versions trigger a rebuild. Account caches are in memory, isolated by account, endpoint, and query. Polling pauses while the page is hidden; no page means no browser polling.

## Costs

Local estimates use API prices for the recorded model and token categories. The built-in table covers GPT-5-era Codex and later models; its verification date is 2026-09-19. Every entry includes an official source. Prices are a bundled snapshot, not a live feed or historical tariff timeline. Spark remains unpriced because a public USD rate could not be verified. Sol currently uses promotional prices guaranteed at least through 2026-11-21. See [OpenAI pricing](https://developers.openai.com/api/docs/pricing).

For models with a verified long-context rule, a single request with **more than 272,000 input tokens, including cached input**, uses 2× input/cache rates and 1.5× output rates for the entire request. It is not a charge on only the excess or on cumulative session usage. A request after compaction is evaluated using its own input length. GPT-5.4 Mini/Nano and older models do not inherit this rule. Cumulative-only legacy records without per-request input are estimated at standard rates.

Existing local logs do not record the actual `service_tier`, so Fast premiums are not inferred from today's configuration. API processing tiers and ChatGPT subscription credit multipliers are different. Estimates exclude tool charges and are not subscription bills. See [API Fast mode](https://developers.openai.com/api/docs/guides/fast-mode).

Custom `PRICING_FILE` entries replace matching built-in records; remaining unknown models may be filled from `~/.cache/codeburn/litellm-pricing.json`. Missing required prices remain unknown, with the calculable subtotal retained. CodeBurn currency settings and a matching exchange-rate cache are supported; otherwise USD is used.

Prices in custom JSON are **USD per token**, not per million:

```json
{
  "updatedAt": "2026-09-19",
  "models": {
    "gpt-6-astra": {
      "inputCostPerToken": 0.00001,
      "cacheReadCostPerToken": 0.000001,
      "cacheWriteCostPerToken": 0.0000125,
      "outputCostPerToken": 0.00005,
      "source": "https://developers.openai.com/api/docs/models/gpt-6-astra",
      "longContext": {
        "aboveInputTokens": 272000,
        "inputMultiplier": 2,
        "outputMultiplier": 1.5
      }
    }
  }
}
```

Omit `longContext` to always use the supplied flat prices. Missing cache prices are not zero. Custom files are reloaded when statistics are read. The separate calculator always applies the prices entered there to the supplied total quantities.

## Privacy and security

Credentials stay on the backend. The browser receives no access token, account ID, email, or raw conversation. Account queries use fixed ChatGPT endpoints; auth files and tokens are not modified. Never commit auth files, raw sessions, or `.state-codex-tally`.

Public snapshots contain a version, collection time, month, and allowed metrics. They exclude project paths, account/session identifiers, prompts, costs, and quotas. Custom model names may contain internal information; review them before publishing models. Replace any inherited snapshot after forking before deploying. Disabling sharing cannot erase downloads or old Git commits.

The private dashboard checks Host and Origin, rate-limits sign-ins, and uses HttpOnly/SameSite cookies. It prevents framing. Public routes are read-only and use sandbox/content-security restrictions. Anonymous reads cannot run local scans, query private account endpoints, or submit data. A generated password appears in redirected console logs as well as the console.

Report vulnerabilities privately through the repository's **Security → Report a vulnerability** when available. Otherwise, open an issue requesting a private contact channel without exploit details. Do not publish credentials or actionable vulnerability details.

## Development and releases

Use Go 1.27+, Git 2.31+ for sync, Node.js for JavaScript syntax checks, and Python 3.11+ for packaging. The executable itself needs none of these runtimes except Git for sync.

```bash
go build -trimpath -o codex-tally ./cmd/codex-tally
go test -race ./...
go vet ./...
```

The root `go build .` and `go run .` compatibility entry points remain available. CI and packaging use `cmd/codex-tally`.

Versions use strict SemVer without `v`, for example `0.1.0` or `0.1.0-rc.1`. Numeric identifiers cannot have leading zeros. Versions are injected through `-ldflags "-X main.buildVersion=..."`; ordinary source builds report `0.0.0-dev`.

Push source first, wait for checks, then push the version tag separately:

```bash
git push origin main
git tag -a 0.1.0 -m "Release 0.1.0"
git push origin 0.1.0
```

Release builds require a clean checkout and exactly one valid tag on HEAD. Tag pushes run checks, build five platform/architecture variants, upload checksums, and create a GitHub Release. Manual Actions runs only upload artifacts. Prereleases are not marked Latest. Published tags and existing release assets are not overwritten automatically.

```bash
python3 scripts/package.py --use-git-tag --release
# Untagged development build:
python3 scripts/package.py --version 0.0.0-dev --out /tmp/codex-tally-build
```

On Windows, use `py -3` and a local output path. Output must be empty. Archives contain a `codex-tally/` directory with the executable, license, and Chinese/English documentation; they exclude credentials, caches, and usage snapshots. Windows/Linux support amd64 and arm64; macOS supports arm64 only. No code signing or macOS notarization is currently performed. When upgrading from 0.0.1, update service/task paths from `codex-dashboard` to `codex-tally`.
